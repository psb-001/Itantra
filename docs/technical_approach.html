EVIDENCE STATUS: every number on this page was measured on a Mac (Apple Silicon, 17 GB RAM), not an Android phone. Phone performance is still untested and will be worse. Items labelled TARGET are goals, not results.

1 · The Idea in One Sentence

You speak on phone A. Instead of transmitting audio (which is huge), the app converts your speech to text, sends only the text over Wi-Fi/Bluetooth, and phone B converts it back to speech. Because text is ~1,000× smaller than audio, voice gets through on links that cannot carry voice — which is exactly ISRO's "low bitrate link" problem.

2 · The Full Loop — and What We Actually Ran

Phone A · Speaker (STT mode)

1Mic records 16 kHz mono audio
2Silero VAD detects pause → cuts a sentence
3Omnilingual ASR 300M INT8 → text
4Text tagged with language, UTF-8 encoded
TEXT ONLY · ~50–110 BYTES
➞
Wi-Fi Direct / Bluetooth
no internet

Phone B · Listener (TTS mode)

1Receives UTF-8 text + language tag
2Piper TTS picks voice (hi / en)
3Synthesises speech at 22 050 Hz
4Plays at max volume, non-interruptible

Push-to-talk = walkie-talkie mode. Release the button = the app behaves like a normal phone (full duplex via the same pipeline).

7 · The Hinglish Question — Honest Answer

You asked for Hindi + English + Hinglish. I checked all 1,668 language IDs the ASR model supports:

  • hin_Deva (Hindi, Devanagari) — SUPPORTED
  • eng_Latn (English) — SUPPORTED
  • hin_Latn (romanised Hindi) — DOES NOT EXIST. Zero romanised Indian languages are in the model.

Recommendation: scope the submission to Hindi + English (both fully proven end-to-end). Treat Hinglish as an optional UI convenience for typed text on phone B only — never claim the ASR outputs it. The problem statement lists 10 languages; we have measured 4, and the deck should say so.

9 · Build Order

1 · Fork the reference app

SherpaOnnxVadAsr already does mic → VAD → ASR → text on Android. This is the fastest legal start.

2 · Add TTS + transport

Ship both Piper voices + espeak-ng-data in assets. Add a Wi-Fi Direct socket; get text A→B.

3 · Push-to-talk & alerts

Hold = STT, other phone = TTS. Alert mode: max volume, audio focus, non-interruptible loop.

Then benchmark on the cheapest phone you can find. That is the real test — everything here is a Mac.

10 · What Is Still Not Proven

  • Android performance — RTF/RAM on low/mid-range phones. Highest priority risk.
  • Noisy real-world speech — FLEURS is clean studio audio; a disaster zone is not.
  • TTS legibility score — needs human listeners, cannot be auto-scored.
  • Wi-Fi Direct reliability — each Android OEM implements P2P differently.
  • Six of ten languages — untested. Marathi measured and weak.
